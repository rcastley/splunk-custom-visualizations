# Native Studio React Adapter

Use this reference only when the CLI template is React or React + TypeScript. Start from the current official generated entry point; do not retrofit React into a framework-agnostic project merely for Canvas rendering.

## Hook usage

Hooks can be used directly, or aggregated with `VisualizationExtensionProvider` and `useVisualizationExtension`. Direct hooks subscribe independently and are sufficient for small components:

```tsx
import {
    useDataSources,
    useDimensions,
    useOptions,
    useTheme,
} from '@splunk/dashboard-studio-extension/react';
import { useEffect, useMemo, useRef } from 'react';
import { createRoot } from 'react-dom/client';
import './visualization.css';

function CanvasVisualization() {
    const canvasRef = useRef<HTMLCanvasElement>(null);
    const { dataSources, loading } = useDataSources();
    const { options } = useOptions();
    const { width, height } = useDimensions();
    const { theme } = useTheme();

    const model = useMemo(
        () => normalizeModel(dataSources?.primary?.data, options),
        [dataSources, options]
    );

    useEffect(() => {
        const canvas = canvasRef.current;
        if (!canvas || !(width > 0 && height > 0)) return;
        const context = prepareCanvas(canvas, width, height);
        if (!context) return;
        draw(context, width, height, { model, loading, theme });
    }, [model, loading, theme, width, height]);

    return <canvas ref={canvasRef} aria-label="Custom visualization" />;
}

const root = document.getElementById('root') || document.body;
createRoot(root).render(<CanvasVisualization />);
```

Use `VisualizationExtensionProvider` when many descendants need a combined state object:

```tsx
import {
    VisualizationExtensionProvider,
    useVisualizationExtension,
} from '@splunk/dashboard-studio-extension/react';

function App() {
    return (
        <VisualizationExtensionProvider>
            <Visualization />
        </VisualizationExtensionProvider>
    );
}
```

The current provider aggregates data, loading, options, dimensions, mode, theme, and errors. Subscribe to tokens separately with `useTokens` when required.

## Rules

- Keep data normalization in `useMemo`; keep Canvas drawing in an effect or a pure helper.
- Include every reactive input in dependency arrays. Do not hide changing Studio state in mutable globals.
- Cancel animation frames and timers in effect cleanup functions.
- Do not recreate the React root on data or option updates.
- Use `useError` for actionable validation failures and clear recovered errors.
- Use `useOptions().setOptions` only for deliberate edit-mode behavior, never to initialize defaults.
- If using `@splunk/themes`, pass the explicit `useTheme()` value. Parent theme styles do not cross the iframe.
- Prefer semantic DOM and accessible text for interactive UI. Canvas marks that drill down need an equivalent discoverable interaction where practical.
- Preserve the versions and dependencies generated by the CLI. React templates may include additional Splunk UI and theme packages; do not remove them without verifying the bundle.

For data shape, configuration, packaging, and verification, follow `studio-framework.md`. For HiDPI setup and pure rendering boundaries, reuse the functions from `studio-canvas-template.md`.
