# Repository Instructions — Splunk Custom Visualizations

This repo contains a portable Agent Skill for both the legacy Splunk visualization framework and the native Dashboard Studio extension framework, plus working examples and local harnesses.

## Key Paths

- **Canonical skill**: `.agents/skills/splunk-viz/SKILL.md` — the full portable skill definition
- **Claude adapter**: `.claude/skills/splunk-viz/SKILL.md` — discovery wrapper only
- **Legacy examples**: `examples/` — each subdirectory is a standalone legacy Splunk viz app
- **Legacy build**: `./build.sh [app_name]` — builds and packages legacy viz apps into `dist/`
- **Legacy harness**: `test-harness.html` and `harness-manifest.json`
- **Native Studio harness**: `studio-test-harness.html` and `studio-harness-manifest.json`

## Rules

- Select the framework before creating files; never mix legacy and native Studio lifecycle or configuration conventions
- Legacy visualizations go in `examples/{app_name}/` and use the existing shared `build.sh`
- Native Studio projects use the directory structure generated by `@splunk/create --mode=dashboard-studio-extension`
- Use ES5 syntax only in legacy `visualization_source.js`; native Studio entries use the generated ES2017/esbuild target
- Always handle HiDPI, null ctx, and zero-size canvas
- Keep `visualization.css` background transparent by default
- For legacy vizs, every setting in `formatter.html` must appear in `savedsearches.conf.spec`, JS defaults must match formatter defaults, and `formatData` must not read `config`
- For native Studio vizs, every editor option must appear in `config.json` `optionsSchema`, code fallbacks must match schema defaults, and result data must support the columnar shape
- Use the framework-specific harness: legacy bundles in `test-harness.html`, native bundles in `studio-test-harness.html`
- Package legacy vizs with `./build.sh`; package native Studio vizs with the scripts generated by the official CLI
